 ● The user asks about stereotypes «FeatureType», «DataType», «ObjectType» in the original CityGML conceptual model (UML). Explain origin: these come from ISO/TC211 harmonized model / GML (ISO 19136) metamodel, ISO 19103/19109. In GML application 
   schema rules (ISO 19136 / GML 3.2 encoding rules), UML classes are stereotyped to drive the UML→XML Schema mapping:                                                                                                                                 
   ... (12 more lines, ctrl+o to expand)
 
 ● Those stereotypes come from the GML application-schema encoding rules — the UML profile defined by ISO 19136 (GML 3.2) together with ISO 19103 and ISO 19109. CityGML's conceptual model is a UML model built with that profile, and the stereotypes
   are what drive the automated UML → XSD conversion (done with ShapeChange — hence the comment at the top of core.xsd).                                                                                                                               
                                                                                                                                                                                                                                                       
   What each one means:                                                                                                                                                                                                                                
                                                                                                                                                                                                                                                       
   • «FeatureType» — a feature in the sense of ISO 19109 (the General Feature Model): an abstraction of a real-world phenomenon with identity, e.g. Building, CityModel, Address. In the GML encoding, a «FeatureType» class is required to derive from
     gml:AbstractFeatureType — which is exactly why our diagram shows the gml:AbstractFeature stub as the root of the main hierarchy.                                                                                                                  
                                                                                                                                                                                                                                                       
   • «ObjectType» — a GML object: it has identity (gml:id) but is not a feature — it's a building block referenced by features, e.g. ImplicitGeometry, CityObjectRelation. These derive from gml:AbstractGMLType instead (our second stub).            
                                                                                                                                                                                                                                                       
   • «DataType» — a structured data type without identity, just a cluster of attributes, e.g. QualifiedArea, QualifiedVolume, TransformationMatrix4x4. These map to a plain XSD complexType with no GML base class.                                    
                                                                                                                                                                                                                                                       
   (The full profile also has «Enumeration», «CodeList», «Union», «BasicType» etc. from ISO 19103 — RelativeToTerrain in core is an «Enumeration», which is why it stayed a simple attribute in our output.)                                           
                                                                                                                                                                                                                                                       
   Interesting consequence for our project: these stereotypes are recoverable from the XSD we already parse. A class descending from gml:AbstractFeature is «FeatureType», descending from gml:AbstractGML but not a feature is «ObjectType», and      
   having no GML ancestor is «DataType». We already built that ancestry walk in step 05 for the aggregation/dependency split — so if you'd like, a future step could stamp these stereotypes onto the classes in the diagram.

   gml:AssociationAttributeGroup (core.xsd:264), meaning the property can be an xlink:href pointer — and a by-reference target is shareable by many owners, hence *. The alternative convention ("1" = exclusive owner) only applies to by-value       
   containment, which is why compositions get "1".
